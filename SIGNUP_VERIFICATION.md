# Visual authentication prototype

The normal `/`, `/register`, and `/forgot-password` screens are developer-review prototypes. Their form handlers do not call authentication, signup, code delivery, or password reset services. Entered contacts, names, passwords and sample codes stay in form memory and are cleared on completion; Remember Me is visual only.

Login provides Gym Account, Client / Individual, and Dashboard. In a development build, submission saves only a random, credential-free prototype marker to sessionStorage and opens the matching existing page layout. Production cannot activate this navigation (`import.meta.env.DEV` is false); its form shows a prototype notice instead of authenticating. No prototype marker represents a provider identity or grants real authorization.

Gym login first opens `/subscription-request`. Monthly/Annual submissions show a sample Pending state and a dashboard continuation; Skip directly opens the dashboard and creates a fictional Pending example (Sample Gym / Monthly if blank). A separate tab-local scenario contains only the sample gym name, plan, date and Pending status, never credentials or real account IDs. It is restored into the administrator's fictional request list across role switches and refreshes. Reset flow / Reset sample request removes it; no Cloud calls or real approvals occur. Gym and Client profile/account/QR pages use `GYVORA-G-123` and `GYVORA-C-456` with explicit fictional labels. Downloaded QR payloads begin `GYVORA-PROTOTYPE-SAMPLE:` and cannot resolve as real permanent IDs.

Prototype destinations use fixed fictional fixture data. Existing demo helpers are redirected to a separate in-memory Storage adapter, never the browser's legacy account data. CloudProvider bypasses provider reads and ID reservations; private server middleware rejects prototype calls. Existing saved-account authorization remains unchanged. Account-type route restrictions prevent opening another type's design through this marker. Query caches are cleared before prototype entry. Refresh rebuilds fixtures; leaving the prototype clears its in-memory store.

Signup offers only Gym and Client, with Send Code, Verify, and Create Account stages. Verification accepts any non-empty sample code within a contact-bound ten-minute challenge and visibly identifies simulation. Final submission shows success without creating an account. Recovery similarly demonstrates send/resend, verification and new password without sending codes or changing passwords.

Real authentication is deliberately not wired to these review forms. Reconnecting production requires a separately reviewed provider login flow and server-only send/verify adapters with verified email/SMS senders, rate limits, expiration and one-time challenges. Existing signup server functions remain fail-closed; do not make prototype verification an account-creation bypass.
